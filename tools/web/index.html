      Firmware

      Install a new build without the USB cable. In the Arduino IDE use Sketch → Export Compiled Binary, then pick S5GaugePod_Test.ino.bin from the sketch's build folder. The pod keeps running while it uploads, then restarts into the new build. If that build doesn't start properly, the pod goes back to this one by itself.

      How often each reading arrives

      The adapter answers one request at a time, so the readings take turns: RPM and speed every round, then whichever other reading is most overdue. Asks is how often it's wanted (and on boost, under it), Gets how often an answer actually came while you drive, On boost the same during pulls. Readings marked waits in pulls pause on boost so the pull data comes faster; stopped only are read only below about 5 mph (they're for launch detection).

      Talks to the ELM327 directly, for example ATRV, 0100 or 221001 (these go to the engine). To ask another module, put its address first: 7E1:221035 22126A asks the gearbox, up to four at once. The pod pauses its own polling while it waits.

      
    
      ECU self-tests
      
    
      The engine computer tests the catalysts, O2 sensors, valve timing and evap system itself and keeps each result with its pass/fail limits. This reads them all (a second or two). A test only has a real result once the ECU has run it since the codes were last cleared, usually during a steady cruise.
      
    
      
    
      
    
      
    
      Modules on the car
      
    
      Asks every diagnostic address which modules answer (about a minute; the gauges pause), then each one its name. Modules that use VW's older TP2.0 protocol won't show up: an ELM327 can't talk to them. Any module listed here can be asked from the console (710:22F190) or scanned below.
